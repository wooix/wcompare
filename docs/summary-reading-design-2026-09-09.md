# 처음 읽는 논문을 이해하기 위한 요약 개선

2026-09-09 · wcompare

목표는 요약문의 길이를 늘리는 것이 아니라, 독자가 문제·방법·근거·적용 한계를 빠르게 연결하도록 돕는 것이다. 아래 설계는 논문 읽기 방법, 학습 연구, 읽기 인터페이스 연구를 종합한 제품 설계다. 이 앱의 이해 속도 향상을 사용자 실험으로 입증한 것은 아니며, 모든 독자에게 가장 빠른 방법이라고 단정하지 않는다.

## 기존 기능에서 확인한 문제

- 개요와 핵심 정리가 문제·아이디어·결과를 반복했다. 낯선 개념을 설명하거나 작은 입력을 실제 처리 과정에 대입하는 지시가 부족했다.
- 첫 실행에서 네 탭을 모두 생성했다. 사용자는 짧은 첫 안내만 필요해도 나머지 호출까지 기다려야 했고, 진행 표시가 읽는 화면을 덮었다.
- 본문 합치기 과정에서 실제 페이지 경계가 사라졌다. 긴 자료는 앞 70%·뒤 30%를 남기는 방식이어서 중간의 방법·결과가 빠질 수 있었다.
- 요약 주장과 원문 페이지 사이에 이동 경로가 없었다. 숫자를 반드시 넣으라는 지시는 이론·정성 연구에 맞지 않았다.
- 읽은 내용을 떠올리고 자기 말로 설명해 볼 장치가 없었다.

## 구현한 읽기 흐름

1. **핵심 파악**: 800자 이내를 목표로 한 문장 설명, 기존→제안의 차이, 결정적인 검증, 적용 한계, 다음에 볼 원문 2곳을 생성한다. ‘30초’는 훑어보기 분량의 설계 목표이며 생성 시간 보장이 아니다.
2. **작동 원리**: 필수 개념 최대 3개, 입력→중간 처리→출력, 작은 예시, 핵심 근거와 한계, 답을 접은 이해 확인 질문을 생성한다. 예시는 논문 사실과 구별하도록 명시했다. 연구 유형에 따라 처리 알고리즘 대신 관측→추론 과정을 설명한다.
3. **근거 확인**: 기존 절별 목차 기능을 유지하며 각 절의 주장·결과에 페이지 근거를 붙이도록 했다. 수치는 비교 대상·조건·지표와 함께 설명한다.
4. **한눈에 보기**: 일반적인 논문 구성도가 아니라 해당 논문의 입력·구성요소·출력 또는 전제·논증·결론을 도식화한다.

첫 버튼은 현재 탭 하나만 생성한다. 탭을 전환하는 것만으로 모델을 호출하지 않는다. 빈 탭의 시작 버튼으로 필요한 설명을 추가하며, 네 탭을 함께 만들고 싶으면 ‘전체 만들기’를 선택한다. 이미 생성된 내용은 다음 생성 중에도 읽을 수 있다.

## 근거와 상태 관리

- 본문에 `[PDF p.N]`을 넣어 물리적 페이지를 유지한다. 긴 문서는 페이지별로 분산 발췌하고 생략 사실을 화면과 입력에 표시한다. 400페이지를 넘는 매우 긴 자료는 페이지도 분산 선택한다. 이것이 모든 관련 근거를 포함한다는 보장은 없다.
- `[p.N](#paper-page-N)`을 누르면 현재 요약이 속한 문서의 실제 페이지로 이동한다. 좌우 교체 후에도 문서를 따라간다. 뒤로 가기로 이전 위치에 돌아갈 수 있다. 문서 밖 페이지는 오류로 안내한다.
- 링크는 **모델이 제안한 근거 위치**다. 번호 범위는 코드로 검사하지만, 문장이 실제로 그 주장을 뒷받침하는지 자동 검증하지 않는다.
- 텍스트가 전혀 없는 PDF는 생성 전에 멈추고 OCR 필요를 안내한다. 이미지·차트 자체를 모델에 보내지 않으므로 텍스트에 없는 그림 해석은 하지 않도록 했다.
- 기존 캐시와 사용자 프롬프트를 삭제하지 않는다. 기존 형식의 탭에는 다시 생성 안내를 표시한다. 수정한 프롬프트가 있으면 설정의 해당 칸 ‘기본값’으로 새 내장 지시를 적용할 수 있다.
- 답은 모델이 생성하므로 정확도·분량·형식 준수에는 편차가 있다. 자기 설명의 채점이나 학습 성과 판정 기능은 넣지 않았다.

## 검증 기준

기능 검증은 첫 호출 1회, 선택한 탭만 추가 생성, 기존 내용 보존, 원문 링크와 뒤로 가기, 좌우 교체 후 올바른 문서로 이동, 잘못된 페이지 처리, 접힌 답 펼치기, 캐시 복원, 기존 수식·도식·목차·내보내기를 대상으로 한다.

품질 확인은 공개 논문의 실제 Codex 응답에서 핵심 대비·원문 근거·한계 구분·가상 예시 표시·질문 접기 여부를 확인한다. 사용자의 이해 속도 개선은 별도 실험이 필요하다. 비교 실험을 한다면 생소한 논문을 대상으로 기존/개선 UI의 순서를 교차 배정하고, 핵심 설명까지 걸린 시간·개념 질문 정확도·근거 찾기 성공률을 함께 측정해야 한다. 짧게 읽었다는 시간만으로 성공을 판단하지 않는다.

- 실제 Codex, medium effort, 공개 Keshav 논문 2페이지: 개요 706자/약 19초. 상세 설명은 초기 출력에서 소제목에 작성 지시가 섞이는 문제를 발견해 수정했다. 재확인 결과 소제목 7개가 정확하게 표시되고, 접힌 질문 3개와 범위 내 근거 링크가 생성됐다. 재확인 상세 설명은 약 65초/3552자로, 목표 분량 1800~3000자보다 길었다. 분량은 강제 절단하지 않는 프롬프트 목표이므로 편차가 남는다.
- 실제 내용은 경험적 독서 지침을 비교 실험 결과로 과장하지 않았고, 이해용 예시를 실제 실험과 구별했다. 이는 논문 한 편에 대한 점검이며 일반적인 정확도나 이해 속도의 측정값이 아니다.
- `release/wcompare.app`, 빌드 `2026-09-09-002`를 생성하고 실행했다. 실제 생성 응답의 복원, 소제목, 접힌 답, 탭 키보드 탐색과 라이트 테마 화면을 확인했다.
