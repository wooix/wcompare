# 번역본에서 링크가 사라지는 문제 — 원인과 해법

조사일: 2026-07-28 · 대상: transpaper (별도 저장소), PyMuPDF 1.28.0 / MuPDF 1.29.0

## 결론부터

원인은 wcompare가 아니라 **transpaper**에 있고, **고칠 수 있습니다.**
`transpaper/render.py` 에 4줄을 더하면 링크가 100% 살아남습니다 — 실측으로 확인했습니다.

wcompare 쪽은 손댈 것이 없습니다. 링크가 남아 있는 PDF라면 이미 정상 동작합니다(아래 "앱 쪽은 이미 준비돼 있다").

## 증상

번역본(`.ko.pdf`)을 열면 인용·각주·URL 링크가 대부분 죽어 있습니다. 원본과 번역본의 링크 주석을
pdf.js로 세어 비교한 실측입니다.

| 문서 | 원본 링크 | 번역본 링크 | 남은 비율 |
|---|---|---|---|
| arXiv 2404.19737 | 284 (내부 276 / 외부 8) | 9 (내부 1 / 외부 8) | 3% |
| arXiv 2203.15556 | 482 (내부 450 / 외부 32) | 67 (내부 65 / 외부 2) | 14% |

페이지별로 보면 패턴이 뚜렷합니다 — 번역이 일어난 페이지는 링크가 0이 되고, 손대지 않은 페이지는
그대로 남습니다(2404.19737의 10·11쪽은 4개씩 온전).

## 원인

`transpaper/render.py` 의 리댁션 단계입니다.

```python
    for b in targets:
        for ln in (b.lines or []):
            page.add_redact_annot(fitz.Rect(ln.bbox), fill=False)
        ...
    if targets:
        page.apply_redactions(images=fitz.PDF_REDACT_IMAGE_NONE,
                              graphics=fitz.PDF_REDACT_LINE_ART_NONE)   # ← 여기
```

PyMuPDF의 `apply_redactions()` 는 리댁션 사각형과 **겹치는 주석(annotation)을 함께 지웁니다.**
링크도 주석이고, 인용 링크는 본문 줄 위에 정확히 얹혀 있습니다. 리댁션 사각형이 곧 본문 줄이므로
사실상 전부가 함께 사라집니다. transpaper가 링크를 지우려 한 것이 아니라, 글자를 지우는 함수가
링크까지 데려간 것입니다.

## 해법 (적용 완료)

리댁션 **전에** 링크를 걷어 두었다가 **후에** 되꽂습니다. 페이지 기하(MediaBox·회전)는 리댁션으로
바뀌지 않으므로 원래 좌표가 그대로 유효합니다 — 실제로 원본과 번역본의 모든 페이지가
`612x792 r0` 로 동일했습니다.

핵심은 **"그냥 되꽂기"가 아니라 "지우고 되꽂기"** 라는 점입니다. 리댁션은 자기와 겹친 링크만
지우므로 살아남은 링크가 있고, 저장분을 통째로 되꽂으면 그것들이 **두 벌**이 됩니다.
페이지 위쪽 절반만 리댁션해 실측한 결과입니다.

| | 링크 수 | 중복 |
|---|---|---|
| 리댁션만 | 12 (21개 소실) | 0 |
| 그냥 되꽂기 | 45 | **12** |
| 지우고 되꽂기 | 33 | 0 |

앞에 다 지워 두면 리댁션이 무엇을 남겼든 결과가 정확해집니다.

```diff
+    saved_links = []
+    if targets:
+        try:
+            saved_links = page.get_links()
+            for lk in saved_links:
+                page.delete_link(lk)
+        except Exception:  # noqa: BLE001
+            saved_links = []      # 실패하면 예전 동작(링크 소실)으로 후퇴 — 중복보다는 낫다
     for b in targets:
         for ln in (b.lines or []):
             page.add_redact_annot(fitz.Rect(ln.bbox), fill=False)
         ...
     if targets:
         page.apply_redactions(images=fitz.PDF_REDACT_IMAGE_NONE,
                               graphics=fitz.PDF_REDACT_LINE_ART_NONE)
+        for lk in saved_links:
+            try:
+                page.insert_link(lk)
+            except Exception:  # noqa: BLE001 - 링크 하나가 나머지를 망치지 않게
+                pass
         _register()
```

회귀 테스트는 `tests/test_render.py::test_render_page_preserves_links` 입니다 — 번역 블록 **안쪽**
링크(사라졌다가 돌아와야 함)와 **바깥쪽** 링크(살아남되 중복되면 안 됨)를 한 번에 봅니다.

## 검증 결과

실제 `transpaper` 를 arXiv 2404.19737(29쪽)에 그대로 돌려 산출물을 pdf.js로 확인했습니다.

| | 링크 수 | 목적지 해석 | 중복 |
|---|---|---|---|
| 원본 | 284 (내부 276 / 외부 8) | — | — |
| 고치기 전 번역본 | **9** (내부 1 / 외부 8) | — | — |
| 고친 뒤 번역본 | **284** (내부 276 / 외부 8) | **276 / 276** | **0** |

"있기만 한" 것으로는 부족하므로 **wcompare가 실제로 쓰는 엔진(pdf.js)** 으로 다시 열어
목적지가 실제 페이지로 풀리는지까지 확인했고, 번역 자체가 멀쩡한 것도 함께 봤습니다(1쪽 한글 935자).

내부 링크는 `cite.xxx` 같은 이름 목적지(named destination)를 가리키는데, 그 이름표는 문서
전역의 name tree에 있고 리댁션이 건드리지 않습니다. 그래서 복원한 링크가 그대로 해석됩니다.

## 2차 문제: 살렸더니 엉뚱한 자리에 있었다

링크를 되살리고 나서도 사용자 체감은 "링크가 대부분 없다"였습니다. 이유는 좌표입니다 —
링크 사각형은 **영어가 있던 자리**인데, 그 위에 폭이 다른 한국어가 다시 그려집니다.
독자가 보는 인용과 클릭이 먹는 지점이 어긋나고, **누를 수 없는 링크는 없는 링크와 같습니다.**

번역본 링크가 자기 좌표에서 무엇을 덮고 있는지 실측한 결과입니다.

| 문서 | 자기 글자 위에 있는 링크 |
|---|---|
| 2203.15556 | 8% |
| 2404.19737 | 0% |

### 해법: 번역된 글자를 찾아가 다시 정박한다

링크가 덮고 있던 **영어 문자열을 리댁션 전에 함께 기억**해 두었다가, 한국어를 다 그린 **뒤에**
그 문자열을 페이지에서 찾아 링크를 옮깁니다(`_link_needle` / `_reanchor` / `_restore_links`).
그래서 링크 삽입이 리댁션 직후가 아니라 `render_page` 맨 끝으로 내려갔습니다 — 검색 대상이
"완성된 페이지"여야 하기 때문입니다.

순위는 **세로 우선**입니다. 한국어는 자기 줄은 비교적 잘 지키지만 x는 크게 밀립니다.
`et al.,` 같은 흔한 조각은 한 쪽에 열두 번씩 나오는데, 같은 줄을 먼저 보는 규칙이
엉뚱한 인용을 집는 것을 막습니다. 세로로 `LINK_REANCHOR_BAND`(48pt)를 넘어가면 포기하고
원래 자리를 지킵니다 — 그쯤 떨어진 같은 문자열은 대개 다른 인용입니다.

| 문서 | 클릭이 통하는 링크 (전 → 후) |
|---|---|
| 2203.15556 | 8% → **77%** |
| 2404.19737 | 0% → **77%** |

회귀 테스트는 `test_render_page_reanchors_links_to_moved_text` 입니다 — 인용을 줄 앞에서
줄 끝으로 옮기고, 링크가 따라왔는지(`[12]` 위에 있는지)와 실제로 움직였는지를 함께 봅니다.

### 남는 한계

- **상호참조 23%는 못 찾습니다.** `(Table 1)`·`Figure A3`처럼 영어 단어 자체가 한국어로
  번역된 것들입니다("표 1", "그림 A3"). 찾지 못하면 원래 자리를 지키므로, 본문과 무관한
  자리에 헛 클릭 영역이 남습니다. 링크를 지우는 것보다는 낫다고 보고 그대로 둡니다.
  인용(저자명·연도)은 번역되지 않고 남기 때문에 잘 잡힙니다.
- **원본의 링크 사각형이 너무 넓으면 재정박이 무력해집니다.** 사각형이 옆 단어까지 물면
  기억하는 문자열이 `"[12] s"` 같은 것이 되어 번역본 어디에도 없습니다. 실제 논문은
  인용을 꼭 맞게 감싸므로 문제되지 않지만, 테스트 픽스처를 만들 때는 주의해야 합니다.

## 함정: `get_links()` 는 검증에 쓰면 안 된다

`apply_redactions()` 이후 같은 세션에서 `page.get_links()` 를 부르면 **메모리 캐시가 돌아와서**
방금 넣은 링크가 보이지 않습니다. 이것 때문에 처음에는 해법이 실패한 줄 알았습니다.

```
[2a] 리댁션 직후 링크        = 0
[2b] 같은 page 객체에 재삽입 → 0   ← 캐시. 실제로는 들어가 있다
[4]  저장·재오픈 후          → 33  ← 진실
```

판정은 반드시 **저장한 뒤 다시 연 파일**에서 하십시오. transpaper도 `doc.save(out)` 으로 끝나므로
그쪽이 실제 산출물의 진실입니다.

## 앱 쪽은 이미 준비돼 있다

링크가 살아 있는 PDF라면 wcompare는 손댈 것 없이 동작합니다. 확인한 것들:

- `PDFViewer` 를 `PDFLinkService` 와 함께 만들고 주석 레이어를 그립니다 (`src/renderer/pdfViewer.js`).
- 주석 레이어 CSS(`pdf_viewer.css`)를 번들에 복사해 `index.html` 에서 읽습니다 (`esbuild.mjs`).
- 내부 링크 클릭은 `linkService` 를 지나며 이동 히스토리를 쌓습니다 → 뒤로/앞으로(`⌘←/→`)가 동작.
  e2e `pdf-dual.spec.js` 의 "링크 히스토리" 테스트가 `.annotationLayer a` 를 실제로 클릭해 덮고 있습니다.
- 외부 URL은 `will-navigate` 를 막고 `setWindowOpenHandler` → `shell.openExternal` 로 보내
  기본 브라우저에서 엽니다 (`src/main/main.js`). 렌더러가 외부 주소로 항해하지 않으므로 CSP도 그대로입니다.
