# wcompare 기능 현황과 로드맵

> 2026-07-15, `feat/pdf-dual-viewer` 브랜치 기준. 멀티에이전트 코드 감사(인벤토리 4 렌즈 · 아이디어 3 렌즈 · 적대적 검증 2)로 소스에서 직접 추출·검증한 결과입니다. 제안 28건 중 27건이 실현 가능 판정을 받았고 1건(3-way 비교)은 기각됐습니다.

결론부터 말하면: **"보기(view)"는 이미 완성 단계이고, "비교(compare)·주석 관리·내보내기(export)"가 비어 있습니다.** 그리고 wcompare만이 가진 자산 — *원문과 번역본이 페이지 지오메트리를 공유하는 오버레이 번역 구조* — 을 활용한 독자 기능이 가장 투자 효율이 높습니다.

## 1. 현재 기능 전체 정리

| 듀얼 페인 뷰어 | Open Left/Right, DnD, 메뉴, CLI 인자 | pdf.js 6 기반, .pdf 열면 자동 PDF 모드 전환 |

| Fit(폭 맞춤) | `Fit: ON/OFF` 토글 | 최초 로드 시 ON, 창 리사이즈에 자동 재적용 |
| Sync 스크롤 | `Sync: ON/OFF` 토글 | 세로+가로 모두 비율 동기화, 순환 이벤트 차단 |

- esbuild 번들(`npm run build`), macOS `.app` 패키저(`npm run package:mac`, 의존성 0)
- node:test 단위 테스트 + Playwright E2E

### P1 4건의 핵심 설계 포인트

**목차 패널** — `pdfViewer.js`에 `getOutline`/`goToDest`를 노출하면 `goToDestination`이 이미 링크 히스토리 몽키패치를 지나므로 뒤로/앞으로가 공짜로 연동됩니다. 검증에서 나온 조정 2가지: dest 없이 url/action만 있는 outline 항목 분기 필수, 드로어는 absolute 겹침 대신 **pane을 flex 2열로 나누고 열림/닫힘 시 Fit 재계산**(안 그러면 page-width 페이지의 왼쪽 220px이 가려집니다).

**야간 모드** — `#pdfview.night .page canvas { filter: invert(0.9) hue-rotate(180deg) }` 한 블록이 본체입니다. 마커 레이어는 canvas의 형제라 필터를 받지 않지만, 형광펜의 `multiply`는 어두운 캔버스에서 안 보이므로 night에서는 `screen`으로 보정합니다. 검색 하이라이트 색도 night용 한 줄 보정을 권장. **독립 토글 버튼**으로(btn-theme은 Monaco 테마와 묶여 있어 겸용하면 상태가 꼬입니다).

**PDF 텍스트 diff** — `getTextContent()`의 transform으로 단어별 0~1 rect를 만들고(마커와 같은 좌표계) Myers diff로 add/del을 산출, 마커와 동일 패턴의 `.diff-layer`로 렌더합니다. 검증에서 정리된 원칙: *추출은 전량 비동기, diff는 밴드 제한 Myers 1회, 렌더만 lazy*. `items[].str`은 단어가 아닌 청크라 rect는 근사임을 전제로 줄 단위 병합(coalesce)을 기본값으로. diff 라이브러리는 CSP 때문에 esbuild 번들에 포함해야 합니다.

**변경점 탐색** — diff 결과를 `(page, y)` 정렬한 changeList + `◀ 변경 / 변경 ▶` + 카운트. F7 재사용은 keydown이 아니라 **MENU 핸들러(`menu:next-diff`)의 모드 분기**가 정확한 지점입니다(메뉴 액셀러레이터는 keydown으로 못 가로챕니다). 순수 삽입/삭제의 반대편 위치는 1차에서 '같은 페이지 상단' 보수적 보간으로.

## 3. 직접 설계한 독자 기능: wcompare에서만 나올 수 있는 것들

핵심 통찰은 하나입니다 — **transpaper의 오버레이 번역은 페이지 지오메트리를 보존하므로, 원문 p.N의 (x, y, w, h)는 번역본에서도 같은 내용을 가리킵니다.** 이 좌표 동형성(geometry isomorphism)이 아래 기능들의 공통 기반입니다. 8건 전부 적대적 검증을 통과했고, 검증에서 나온 조정을 반영해 적었습니다.

### 3.1 마커 미러링: 원문에 칠하면 번역본에도 같은 자리 `M · P1`

한쪽에 형광펜을 긋는 순간 반대편 같은 좌표에 미러 마커(점선 테두리·낮은 투명도)가 자동 생성됩니다. 번역 완료 핸들러가 `setPair(orig, ko)`로 문서쌍을 등록하고(파일명 규칙 `<이름>.ko.pdf` 자동 감지 포함 — ko 쪽이 미러 대상), 마커 추가 시 반대편 markerStore에 미러 항목을 push합니다. **조정 반영**: srcId 양방향 참조 대신 *쌍 공통 groupId 하나*로 삭제·sanitize를 단순화, overflow 페이지(지오메트리 붕괴)에서는 미러를 억제하거나 표시를 다르게(3.5 번역 상태 맵과 연동), `renderPage` 1줄 노출 선행. `.wcproj` VERSION 2로 상향(v1은 계속 열림).

### 3.2 미러 점프: Alt+클릭으로 반대편 같은 위치로 순간 이동 `S · P1`

Sync를 꺼 두고 번역본만 읽다가 "이 문장 원문이 뭐였지?" 싶을 때 Alt+클릭 한 번 — 반대편이 같은 페이지·같은 위치로 스크롤되고 도착 지점이 1.5초 펄스로 깜빡입니다. 이동 직전 위치는 기존 링크 히스토리에 쌓여 ⌘←로 복귀합니다. **조정 반영**: 기준 박스는 textLayer가 아니라 항상 존재하는 pageDiv로(점프 직후 대상 페이지는 대개 미렌더), `locate()` 1줄 노출 선행. *검증 평: P1 중 가장 싸고 확실한 항목.*

### 3.3 원문 렌즈: 호버로 반대편 문장 미리보기 `M · P2`

Alt를 누른 채 번역본 문장에 마우스를 올리면 커서 아래 줄에 해당하는 원문 텍스트가 작은 카드로 뜹니다. 시선 이동 없는 원문 대조 — 오버레이 번역 구조에서만 가능한 기능입니다. **조정 반영**: 반대편 textLayer는 화면 밖이라 거의 항상 파괴돼 있으므로(pdf.js 버퍼 10), `getTextContent()` 기반 단일 구현 + 페이지당 캐시로 처음부터 설계(코드가 절반으로 줍니다). 2단 레이아웃 대비 x 범위 제한 필수.

### 3.4 용어쌍 수집: 원문·번역 카드로 모아 용어집 만들기 `M · P2`

검수 중 우클릭 한 번으로 원문·번역 텍스트 쌍을 카드로 수집하고 메모를 달아 프로젝트에 저장, CSV/Markdown 용어집으로 내보내 다음 번역이나 팀 공유에 재사용합니다. **조정 반영**: 상한을 항목 500개·텍스트 500자로, dstText 자동 추출(3.3 의존)은 실패를 정상 흐름으로 두고 빈 값+인라인 편집이 기본 UX. *부수 발견: 저장 경로에 2MB 검증이 없어 "저장은 되는데 다시 못 여는" 프로젝트가 이미 가능한 상태 — 별도 수정 작업으로 분리했습니다.*

### 3.5 번역 상태 맵: 페이지별 완역/overflow/원문유지 미니맵 `M · P2`

transpaper가 페이지마다 이미 출력하는 `translated K blocks, M overflowed` 정보를 버리지 않고, 페인 사이 얇은 미니맵에 초록(완역)/노랑(overflow)/빨강(원문 유지)으로 칠합니다. 클릭하면 그 페이지로 이동해 검수를 시작합니다. `.ko.stats.json` 사이드카로 영속화. **조정 반영**: 1차는 fresh 번역의 캡처+미니맵+상태바 요약까지만. 실패 페이지 판별과 '실패 페이지만 재번역'은 transpaper 쪽 출력/`--pages` 옵션 확인 후 2차로. 사이드카 로드는 main이 경로를 유도하는 전용 IPC로(렌더러 경로 조립 금지 원칙).

### 3.6 앵커 페어링: 두 문서의 스크롤 대응을 손으로 보정 `M · P2`

overflow로 레이아웃이 밀렸거나 판본이 다른 문서에서, "왼쪽의 이 지점 = 오른쪽의 이 지점" 앵커쌍을 몇 개 찍으면 그 사이가 구간별 선형 보간되어 페이지 수가 달라도 나란히 흘러갑니다. `syncScroll.js`(순수 모듈)에 `mapRatio(ratio, anchors)` 추가 + 단위 테스트. **조정 반영**: 역방향 스크롤을 위해 역함수가 필요하므로 **앵커 단조성 강제**(교차 앵커 거부 — 아니면 양방향 sync가 발진합니다)를 순수 함수 스펙에 포함, 저장 단위는 scrollTop 비율이 아니라 `{page, offset}`으로(lazy 페이지 높이 확정 전후 드리프트 방지).

### 3.7 읽기 세션 자동 이어보기 `M · P1`

프로젝트 저장을 잊어도, 같은 PDF 쌍을 다시 열면 상태바에 "이어보기 ↩ (p.37, 3일 전)" 버튼이 떠서 클릭 한 번에 스크롤·배율·마커가 복원됩니다(강제 복원은 하지 않습니다 — 새로 읽고 싶을 수도 있으므로). `userData/doc-state/<sha1(정렬된 쌍)>.json`, LRU 50개. 메인은 openedPdfs allowlist 검증으로 렌더러 임의 경로 기록을 차단합니다. **조정 반영**: 키는 좌우 정렬된 쌍으로 정규화(Switch 후에도 동일 키), 저장 포맷은 처음부터 `{page, offset}` 기반, projectSnapshot과 코드 공유. *검증 평: P1 중 구현 리스크 대비 체감 가치가 가장 높음.*

### 3.8 대조 PDF 내보내기: 원문·번역 2-up + 마커 번인 `L · P3`

화면의 "왼쪽 원문 / 오른쪽 번역 + 형광펜" 상태 그대로를 한 장짜리 가로 페이지에 담은 검토용 PDF로 내보내, wcompare가 없는 동료에게 전달합니다. **조정 반영(더 싼 대안 우선)**: pdf-lib 도입 전에 숨은 BrowserWindow에 2-up HTML을 렌더해 `webContents.printToPDF` — 의존성 0, 번들 변경 0. 벡터 품질·마커 번인이 꼭 필요해질 때만 pdf-lib 경로로 승격.

## 4. 추천 로드맵

우선순위 원칙: ① 싸고 확실한 것부터(S/P1), ② wcompare 정체성(번역 대조)을 완성하는 축, ③ '비교 도구' 축, ④ 공유·출구.

**M1 — Quick wins (전부 S 공수)**
야간 모드(2.2) → 미러 점프(3.2) → 최근 파일(2.8) → 마커 색상(2.6) → 텍스트 전체 추출(2.5)

**M2 — 번역 대조 워크플로 완성 (독자 기능 축)**
마커 미러링(3.1) → 읽기 세션 이어보기(3.7) → 번역 상태 맵(3.5) → 원문 렌즈(3.3) → 용어쌍 수집(3.4)

**M3 — 진짜 '비교 도구'로**
PDF 텍스트 diff(2.3, L) → 변경점 탐색(2.4) → 비주얼 diff(2.12) → 페이지 정렬 매핑(2.13) → 앵커 페어링(3.6)

**M4 — 공유와 출구**
TOC 패널(2.1) + 썸네일(2.11, 드로어 인프라 공유) → 스티키 노트(2.7) → Diff 리포트(2.14) → 대조 PDF 내보내기(3.8) → 주석 PDF 내보내기(2.16)

**하지 않기로 한 것**: 3-way 머지(기각 — 외부 머지 툴 연동으로 대체), 인쇄(내보내기에 위임), 디렉터리 비교(수요 확인 전 보류).

## 부록: 검증에서 걸러진 함정 (구현 시 필독)

- `.wcproj` 2MB 상한이 **열기에만 있고 저장에는 없음** — 용어쌍/스티키 노트처럼 텍스트를 프로젝트에 넣는 기능 전에 반드시 저장 경로 검증 추가 (별도 작업 분리됨).
- F7 등 메뉴 액셀러레이터는 렌더러 keydown으로 가로챌 수 없음 — MENU 핸들러에서 모드 분기.
- 화면 밖 페이지의 textLayer는 pdf.js 버퍼(10)에 의해 파괴됨 — 반대편 텍스트가 필요한 기능은 `getTextContent()` 경로가 주 경로.
- `PDFPageView.reset()`은 커스텀 자식 DOM을 지움 — 모든 오버레이는 `pagerendered` 멱등 재부착 패턴 필수(기존 마커 레이어와 동일).
- overflow 페이지에서는 원문↔번역 좌표 동형성이 깨짐 — 좌표 미러링 계열 기능은 번역 상태 맵과 연동해 방어.
- 렌더러는 경로를 조립하지 않는다 — 새 파일 IO는 전부 main이 경로를 유도하는 전용 IPC로.
