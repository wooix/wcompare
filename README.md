# wcompare

파일 2개를 Beyond Compare처럼 나란히 비교·편집·저장하는 매우 심플한 Electron 데스크톱 앱.
확장자에 따라 **syntax 하이라이트 / lint / vim 모드**가 자동 적용됩니다.

핵심 엔진(diff·syntax·vim·lint)은 직접 구현하지 않고 검증된 라이브러리/CLI에 위임합니다:
[Monaco Editor](https://microsoft.github.io/monaco-editor/)(diff·syntax), [monaco-vim](https://github.com/brijeshb42/monaco-vim)(vim), [ruff](https://docs.astral.sh/ruff/)·[ESLint](https://eslint.org/)(lint).

## 요구사항

- Node.js 18+ (개발 환경 기준 Node 26)
- lint를 쓰려면 해당 CLI가 PATH에 설치되어 있어야 합니다(없으면 조용히 건너뜀):
  - Python(`.py`): [`ruff`](https://docs.astral.sh/ruff/installation/)
  - JS/TS(`.js`/`.ts`): [`eslint`](https://eslint.org/docs/latest/use/getting-started)

## 설치 & 실행

```bash
npm install
npm run build      # 렌더러/preload/Monaco 워커 번들
npm start          # 앱 실행
# 또는 두 파일을 바로 열기:
npx electron . path/to/old.py path/to/new.py
```

개발 중에는 `npm run dev`(esbuild watch + electron)를 사용합니다.

## 화면 테마

설정창(File → Settings…) 맨 위에서 **다크 / 라이트**를 고릅니다. 툴바·패널·요약·편집기가 함께 바뀌고,
선택은 저장되어 다음 실행까지 이어집니다.

PDF **야간 모드**(`Night`)는 이와 **별개**입니다 — 야간 모드는 PDF 페이지 자체를 반전하는 기능이라,
"밝은 UI + 반전된 PDF" 같은 조합을 쓸 수 있도록 테마에 묶지 않았습니다.

## 파일 열기

앱은 **PDF 모드로 시작**합니다. 빈 왼쪽 화면의 URL 입력창이 곧 시작 화면입니다.
텍스트 파일을 열면 자동으로 diff 모드로 바뀝니다.

- 툴바 **Open Left / Open Right** 버튼 (파일 선택 대화상자)
- 편집기 패널에 파일 **드래그앤드롭** (왼쪽 절반=좌, 오른쪽 절반=우)
- CLI 인자: `electron . a.py b.py`
- **URL로 PDF 열기**: PDF 모드에서 왼쪽 화면이 비어 있으면 URL 입력창이 나타납니다 ([아래](#url로-pdf-열기))
- **Finder에서 열기**: PDF를 더블클릭하거나 앱 아이콘에 끌어다 놓기 ([아래](#pdf-기본-앱으로-지정))

### PDF 기본 앱으로 지정

`.app` 은 PDF 문서 타입을 선언하므로 Finder의 **"다음으로 열기"** 목록에 wcompare가 나타납니다.
기본 앱으로 바꾸는 방법은 두 가지입니다.

- **설정창 → PDF 기본 앱 → `wcompare로 지정`**. [duti](https://github.com/moretension/duti)
  (`brew install duti`)가 설치돼 있을 때만 동작합니다 — macOS는 파일 형식의 기본 앱을 바꾸는 API를
  앱에 열어 주지 않아(`setAsDefaultProtocolClient` 는 URL 스킴 전용) 외부 도구가 필요합니다.
- **Finder에서 직접**: PDF 하나 선택 → `⌘I` → "다음으로 열기"에서 wcompare → **모두 변경…**

빌드 직후 목록에 안 보이면 LaunchServices에 등록해 주십시오.

```bash
/System/Library/Frameworks/CoreServices.framework/Frameworks/LaunchServices.framework/Support/lsregister -f /Applications/wcompare.app
```

Finder에서 연 파일이 놓이는 자리:

| 상황 | 결과 |
|---|---|
| 창이 없음 | 새 창에 엽니다 |
| 한쪽만 차 있음 | **비어 있는 반대쪽**에 엽니다 (바로 대조 상태가 됩니다) |
| 양쪽 다 차 있음 | **새 창**에 엽니다 (보던 문서를 밀어내지 않습니다) |
| 두 개를 한꺼번에 선택 | 한 창의 좌·우에 나란히 엽니다 |

## 단축키

| 동작 | 단축키 |
|---|---|
| 저장(현재 패널) | `Ctrl/Cmd+S` 또는 vim `:w` |
| 다음 / 이전 차이 | `F7` / `Shift+F7` |
| 왼쪽→오른쪽 / 오른쪽→왼쪽 블록 복사 | `Alt+→` / `Alt+←` |
| 파일 열기(좌 / 우) | `Ctrl/Cmd+O` / `Ctrl/Cmd+Shift+O` |
| vim 모드 / 공백 무시 / 테마 토글 | View 메뉴 또는 툴바 버튼 |

vim 모드는 기본 ON입니다. 포커스된 패널이 키를 받으며, 하단 상태바에 vim 상태가 표시됩니다.

## lint 동작 방식

- **완전 격리 모드**로 실행합니다: `ruff --isolated`, `eslint --no-config-lookup`(wcompare 번들 기본 config 사용).
- 즉 **여러분 프로젝트의 `eslint.config.js`/`pyproject.toml`은 자동으로 읽지 않습니다.** 이는 의도된 설계로,
  열린 파일 옆의 설정 파일이 lint 시 자동 실행되어 임의 코드가 도는 것(RCE)을 막기 위함입니다.
- 진단은 편집기에 마커(빨간/노란 물결)로 표시되고, 파일 저장·편집(디바운스) 시 갱신됩니다.

## PDF 동기 스크롤 뷰어

동일 format의 PDF 2개(예: 같은 문서의 영어판·한글판)를 좌/우에 띄우고 **함께 스크롤**합니다.

- **진입**: `.pdf` 파일을 열면 자동으로 PDF 모드로 전환됩니다(`electron . a.pdf b.pdf`, 파일 대화상자, 드래그앤드롭). 툴바 **PDF Mode / Diff Mode** 버튼으로 수동 전환도 됩니다.
- **스크롤 동기**: 한쪽을 스크롤하면 다른 쪽이 **비율 기반**으로 같이 움직입니다(양방향). 페이지 높이가 조금 달라도 비례로 따라갑니다.
- **줌**: 툴바 `−` / `+`, `Cmd/Ctrl +·−`, `Ctrl+휠` 로 양쪽이 같은 배율로 확대·축소됩니다.
- **Fit**: `Fit: ON/OFF` 는 **화면 너비에 맞추는 상태**입니다. 켜 두면 창 크기를 바꿔도 계속 너비에 다시 맞춥니다.
  직접 줌하면 자동으로 꺼지고, 다시 켜면 너비 맞춤으로 복귀합니다.
- **Switch**: `⇄ Switch` 로 좌우 문서를 맞바꿉니다. 이미 파싱된 문서 객체만 교환하므로 재파싱이 없습니다.
  한쪽만 열려 있으면 반대편으로 옮깁니다.
- **동기 토글**: `Sync: ON/OFF` 버튼으로 한쪽만 따로 볼 수 있고, 다시 켜면 즉시 재정렬됩니다.
- **페이지**: 상단 `Page n / N` 입력으로 양쪽이 함께 이동하고, 하단 상태바에 `L n/N  R n/N  배율%`가 표시됩니다.
- **검색**: `⌘F` 로 검색창에 들어가 **양쪽에서 동시에** 찾습니다. 일치 수는 `L 2/7  R 0/0` 처럼 좌우를 따로 보여줍니다
  (원문과 번역본은 텍스트가 달라 한쪽만 걸리는 게 정상입니다). `Enter` 다음 일치, `⇧Enter` 이전 일치, `Esc` 로 지웁니다.
  새 검색은 지금 보고 있는 쪽에서 시작합니다.
- **링크 히스토리**: 문서 안의 링크(인용·목차 등)로 튄 뒤 `◀`/`▶` 버튼, `⌘←`/`⌘→`,
  또는 **마우스 뒤로·앞으로 버튼**으로 원래 보던 자리로 돌아갑니다. 좌우 스크롤 위치를 함께 기록하므로
  `Sync: OFF` 상태에서도 두 pane이 각자 제자리로 돌아갑니다.
- **복사**: 텍스트를 드래그해 `⌘C`, 또는 우클릭 → `복사`.

### URL로 PDF 열기

PDF 모드에서 **왼쪽 화면에 문서가 없으면** 가운데에 URL 입력창이 나타납니다.
PDF 주소를 붙여넣고 `Enter`(또는 `열기`)를 누르면 내려받아 그 자리에 엽니다.

- 다운로드는 **메인 프로세스**가 합니다. 렌더러 CSP(`connect-src 'self'`)가 외부 요청을 막고 있기도 하고,
  무엇보다 "경로를 만들어 내는 주체는 메인 하나"라는 이 앱의 화이트리스트 원칙을 지키기 위함입니다.
- 받은 파일은 보관 폴더의 `downloads/` 에 저장됩니다 → 이후 번역·마커 저장·프로젝트 저장이
  로컬에서 연 PDF와 **완전히 동일한 경로**를 지납니다.
- `http` / `https` 만 허용하고, 응답이 진짜 PDF인지 `%PDF-` 헤더를 **바이트로** 확인합니다
  (200으로 돌려주는 HTML 오류 페이지가 흔하므로 content-type만 믿지 않습니다). 크기 상한은 200MB.
- **같은 URL을 다시 열면 내려받지 않고 이미 있는 파일을 엽니다.** URL→파일 색인을 보관 폴더에 두고
  받기 *전에* 확인합니다. 이게 없으면 열 때마다 새로 받고, 내용이 한 바이트라도 다르면 `paper-2.pdf`로
  비켜 저장되는데 — 그러면 번역 출력 경로도 `paper-2.ko.pdf`라는 새 경로가 되어 이미 만들어 둔
  번역본을 못 찾고 **번역을 처음부터 다시 돌립니다**.
- 서버 쪽 문서가 갱신됐다면 **⌥(Alt)를 누른 채 `열기`** 를 눌러 다시 받습니다. 버전 없는 arXiv 주소처럼
  같은 URL이 최신본을 주는 경우를 위한 탈출구입니다.
- 실패하면 입력창 아래에 이유가 그대로 표시되고, 고쳐서 다시 시도할 수 있게 입력값은 남습니다.

## 보기 형태 3종 + 논문 요약

PDF 모드 툴바의 `대조 | 요약 | 3분할` 로 화면 구성을 고릅니다. 목적은 **논문을 빠르게 이해하고,
원문·번역본을 오가며 읽는 것을 돕는 것**입니다.

| 형태 | 구성 | 쓰임 |
|---|---|---|
| **대조** | 원문 \| 번역 | 문장 단위 대조 읽기 |
| **요약** | 원문 \| 요약 | 논문을 처음 훑을 때 |
| **3분할** | 원문 \| 번역 \| 요약 | 요약으로 지도를 잡고 원문·번역을 오갈 때 |

형태 전환은 **어떤 열을 보여줄지만** 바꿉니다. 문서를 닫거나 다시 파싱하지 않으므로 오가더라도
열려 있던 PDF·마커·스크롤 위치가 그대로 남습니다. 선택한 형태는 다음 실행까지 기억됩니다.
번역이 끝나 오른쪽에 결과가 열릴 때 그 열이 숨어 있으면 자동으로 3분할로 넓힙니다 —
기다린 번역본이 보이지 않는 열에 떨어지지 않도록.

### 요약 패널의 세 탭

`논문 요약 생성` 을 누르면 세 가지를 차례로 만듭니다. **Overview가 가장 짧고 빨라 먼저 뜨므로**
나머지를 기다리는 동안 읽을거리가 생깁니다.

1. **Overview** — 전체를 최대한 간략히. 무엇을 푸는 문제인가 / 기존 방법의 한계 / 핵심 아이디어 /
   검증 방법 / 핵심 수치 / 저자가 밝힌 한계. 30초 안에 "이 논문을 읽을지" 판단하는 것이 목표입니다.
2. **절별 요약** — PDF 목차 순서를 그대로 따라 절마다 요약과 해석을 답니다. 목차 항목의 `dest`를
   페이지 번호로 환산해 그 범위의 본문만 잘라 넘기므로, 모델이 절 순서를 임의로 바꾸지 않습니다.
   목차가 없거나 링크가 끊긴 PDF는 본문 전체를 순서대로 넘기는 방식으로 물러섭니다.
3. **흐름도** — 논문의 논리 흐름을 mermaid 다이어그램으로. 문제 제기 → 기존 한계 → 핵심 아이디어
   → 방법 → 실험 → 결과 → 한계 순서로 잇습니다.

### 뷰어

Overview와 절별 요약은 **마크다운 뷰어**(marked)로 그립니다. 제목·목록·중첩 목록·인용·코드·표·링크와
**LaTeX 수식**을 지원합니다 — 논문 요약에는 `$N$`, `$$L = \frac{1}{N}\sum_i x_i$$` 같은 수식이 흔히
섞여 오는데, 이걸 KaTeX가 글자로 그려 줍니다(폰트까지 앱에 동봉되어 네트워크를 쓰지 않습니다).

LLM 출력은 신뢰할 수 없는 입력이므로 **DOMPurify로 정화한 뒤에만** 화면에 넣습니다.

탭바 오른쪽의 `A−` / `↺` / `A+` 로 **글씨 크기**를 조절합니다(10~24px). 크기 하나를 바꾸면 제목·본문·
코드·수식이 함께 움직이고, 고른 크기는 다음 실행까지 유지됩니다.

### 알아 둘 점

- 요약은 번역과 같은 엔진(설정의 `agy` / `claude`)을 씁니다. `<엔진> -p "<프롬프트>"` 로 한 번씩 부릅니다.
- **하나가 실패해도 나머지는 계속 만들고, 부분 성공도 캐시합니다.** 흐름도 하나 때문에 요약 전체를
  잃는 것이 가장 아까운 실패이기 때문입니다.
- 결과는 보관 폴더의 `summaries/` 에 PDF 경로별로 캐시됩니다 → 같은 논문을 다시 열면 **기다림 없이 복원**됩니다.
  다시 만들려면 탭바 오른쪽의 `다시 생성`.
- 요약 재료는 항상 **원문 쪽**(왼쪽이 있으면 왼쪽)에서 뽑습니다. 번역본을 다시 요약하면 번역에서
  한 번 잃은 것 위에 요약 손실이 겹치기 때문입니다.
- 본문이 매우 길면 가운데를 덜어내고 앞뒤를 남깁니다(초록과 결론이 살아남도록).
- mermaid는 앱 안에 동봉되어 있어 네트워크를 쓰지 않습니다. 흐름도 탭을 **처음 열 때만** 로드하므로
  요약을 쓰지 않는 세션에는 비용이 없습니다.

## 마커 (형광펜 / 밑줄)

텍스트를 드래그로 선택한 뒤 **우클릭 → `형광펜` / `밑줄`**, 또는 단축키 `⌘⇧H` / `⌘⇧U`.
마커 위에서 우클릭하면 `마커 삭제`가 나옵니다.

- 좌표는 페이지 기준 **0~1로 정규화**해 보관하고 `%`로 그립니다 → 확대·축소·창 크기 변경을 그대로 따라갑니다.
- 마커는 side가 아니라 **문서**에 묶입니다 → `⇄ Switch` 해도 마커가 문서를 따라 반대편으로 갑니다.
- 마커는 **프로젝트 파일에 저장**됩니다. 프로젝트로 저장하지 않으면 앱을 닫을 때 사라집니다.

## 프로젝트 (.wcproj)

좌/우 파일과 뷰 상태(모드·sync·fit·페이지)와 마커를 한 파일로 저장했다가 그대로 복원합니다.

- **File → Open Project…** (`⌘⇧P`) / **Save Project** (`⌘⇧S`) / **Save Project As…**
- **File → Recent Projects**: 최근 10개. `~/Library/Application Support/wcompare/recent-projects.json`에 보관합니다.
- 파일 경로는 **상대경로를 먼저** 시도하고 절대경로로 폴백합니다 → 프로젝트와 PDF를 함께 옮겨도 열립니다.
- 파일이 없으면 그 쪽만 비우고 나머지는 엽니다(전체 실패하지 않습니다).

보안: 프로젝트 파일은 신뢰할 수 없는 데이터로 취급합니다. 경로 문자열은 렌더러에서 받지 않고
(열기는 메인이 dialog를 띄우고, 최근 항목은 경로가 아니라 **id**로 엽니다), 저장 시에는
**이번 세션에서 실제로 연 파일만** 프로젝트에 담을 수 있습니다. 마커는 읽을 때 개수·좌표를 다시 검증합니다.

렌더링은 [pdf.js](https://mozilla.github.io/pdf.js/)(`pdfjs-dist`)에 위임하며, PDF는 읽기 전용입니다.
PDF 워커도 Monaco 워커처럼 `app://` same-origin으로 로드되어 `sandbox:true`를 유지합니다.

## PDF 한국어 번역 (transpaper)

PDF를 **한쪽에만** 열면 툴바의 `한국어 번역 ▶` 이 활성화됩니다. 누르면 원본을 한국어로 번역해
**반대편 pane에 자동으로 띄웁니다** — 원문과 번역본을 스크롤 동기된 채로 나란히 읽을 수 있습니다.

- 번역은 외부 도구 [transpaper](https://github.com/wooix/transpaper)가 담당합니다(레이아웃을 보존한 오버레이 번역).
- 결과는 원본 옆에 `<이름>.ko.pdf` 로 저장됩니다. 원본 폴더가 읽기 전용이면 임시 폴더에 씁니다.
- **이미 `.ko.pdf` 가 있으면 묻지 않고 그대로 엽니다.** 페이지마다 LLM을 부르는 작업이라 되묻는 순간
  실수로 같은 일을 다시 시키기 쉽습니다. 다시 만들려면 **⌥(Alt)를 누른 채 번역 버튼**을 누릅니다.
- **느립니다** — 페이지당 LLM 호출이 일어나 15페이지 논문 기준 수 분이 걸립니다. 진행 상황은
  번역본이 들어올 **빈 쪽 창에 오버레이**(`한국어 번역 중… 3 / 15 페이지` + 진행바)로 표시되고,
  `번역 취소` 버튼으로 중단할 수 있습니다. 앱을 종료하면 transpaper 프로세스도 함께 정리됩니다.

### 번역본 삭제

번역이 마음에 들지 않을 때는 툴바의 `번역본 삭제` 로 지우고 다시 번역할 수 있습니다.

- **확인을 한 번 받고**, 완전 삭제가 아니라 **휴지통으로** 옮깁니다. 수 분짜리 작업의 결과물이라
  오조작의 대가가 크기 때문입니다. 확인 창의 기본 버튼은 `취소` 입니다.
- 지우는 파일은 **열려 있는 원본에서 유도한 `.ko.pdf` 뿐**입니다. 렌더러는 "이 원본의 번역본"이라고만
  말할 수 있고 삭제 대상 경로는 main이 다시 계산합니다 — 이 앱에서 파일을 없애는 유일한 동작이라
  "경로를 만드는 주체는 main 하나"라는 원칙을 가장 엄격하게 지킵니다.
- 보관 폴더(`translations/`)와 원본 옆, **두 자리를 모두** 봅니다. 보관 위치 설정은 번역한 뒤에도
  바꿀 수 있어서, 지금 설정이 가리키는 자리만 보면 예전 설정으로 만든 번역본이 지울 수 없는 채로 남습니다.
- 지운 번역본이 화면에 열려 있었다면 그 pane이 함께 닫히고, 원본만 남으므로 `한국어 번역 ▶` 이
  다시 활성화됩니다.
- 원본이 열려 있어야 활성화됩니다(번역본만 단독으로 열어 둔 상태에서는 대상을 유도할 수 없습니다).

### 번역본의 링크

번역본에서도 인용·각주·URL 링크가 **그대로 살아 있습니다**. 내부 링크는 클릭하면 해당 위치로
이동하고(뒤로/앞으로 히스토리 포함), 외부 URL은 기본 브라우저에서 열립니다.

원래는 대부분 사라졌습니다 — transpaper가 원문 글자를 `apply_redactions()` 로 지울 때 PyMuPDF가
**리댁션 사각형과 겹치는 주석을 함께 지우는데**, 인용 링크는 본문 줄 위에 정확히 얹혀 있기
때문입니다(arXiv 2404.19737 기준 284개 → 9개). transpaper 쪽에서 리댁션 전에 링크를 걷어 두었다가
뒤에 되꽂도록 고쳐 **284개 → 284개**로 복원했습니다. 원인·해법·검증은
[docs/transpaper-links.md](docs/transpaper-links.md) 에 있습니다.

링크는 **밑줄과 옅은 파랑**으로 표시되고 마우스를 올리면 진해집니다. PDF 본문은 canvas에 그려진
그림이라 웹처럼 글자색을 파랗게 바꿀 수 없어서, 주석 레이어 쪽에 표시를 얹었습니다. pdf.js 기본값은
평상시 완전 투명이라 어디가 링크인지 알 수 없습니다. 야간 모드에서는 밝은 파랑으로 바뀝니다.

번역본에서는 링크가 **번역된 글자를 따라 움직입니다.** 링크 좌표는 영어가 있던 자리인데 그 위에
폭이 다른 한국어가 그려지므로, 그냥 두면 보이는 인용과 눌리는 지점이 어긋납니다(실측 8% / 0%만
제자리). transpaper가 링크의 원래 영어 문자열을 기억했다가 번역 후 그 문자열을 찾아 옮기도록 해
**77%** 가 제 글자 위에 놓입니다. 나머지는 `(Table 1)`·`Figure A3`처럼 단어 자체가 번역돼
찾을 수 없는 상호참조입니다 — 인용(저자명·연도)은 잘 잡힙니다.

> 이 개선이 담긴 transpaper가 필요합니다. 그 전에 만든 `.ko.pdf` 는 링크가 없는 상태 그대로이므로,
> `번역본 삭제` 로 지우고 다시 번역하면 링크가 살아납니다(번역 캐시가 있어 재번역은 대개 몇 초).

### 설치

`transpaper` 실행 파일이 PATH에 있어야 합니다. Finder로 띄운 `.app`은 셸을 거치지 않아
PATH가 `/usr/bin:/bin:...` 뿐이므로, wcompare는 `~/.local/bin`·`/opt/homebrew/bin`·`/usr/local/bin`을
자동으로 PATH에 얹습니다(transpaper가 내부에서 부르는 `agy`/`claude` CLI도 이렇게 찾습니다).

```bash
ln -s <transpaper>/.venv/bin/transpaper ~/.local/bin/transpaper
# 또는 실행 파일 경로를 직접 지정
export WCOMPARE_TRANSPAPER=/path/to/transpaper
```
